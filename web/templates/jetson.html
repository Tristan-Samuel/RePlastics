Jetson

The belt computer runs a TensorRT engine. This machine exports the checkpoint to ONNX. The Jetson builds the engine from that file.

.pt · this machine → .onnx · copied → .engine · Jetson

The .pt is a PyTorch dictionary: ResNeXt-50 weights, plus which output is metal and which is plastic. It stays here. export_onnx.py reads those weights and writes the network by itself, one normalized {{ input_size }}×{{ input_size }} image in and two logits out.

Copy the .onnx and the JSON beside it. Build the engine on the Jetson that will run it. An engine is tied to that GPU and that JetPack, so a file built on another machine stays there.

What the network returns

Input name image, float32, shape 1×3×{{ input_size }}×{{ input_size }}, NCHW, already ImageNet-normalized. Mean {{ mean|join(', ') }}. Std {{ std|join(', ') }}.

Output name logits, shape 1×2. {% for name, index in class_order %}Index {{ index }} is {{ name }}{% if not loop.last %}. {% endif %}{% endfor %}.

Softmax, temperature, and the hold stay outside the graph. The score is the softmax of logits / {{ '%.6f'|format(temperature) }}. When the winner is under {{ '%.2f'|format(threshold) }}, the label is uncertain. A new hold rewrites the JSON. It leaves the ONNX file as it is.

Why the hold is {{ '%.2f'|format(threshold) }}

The measurement on validation picked 0.97. That cutoff held 39 of 1,251 frames to catch four of the five mistakes. One HDPE bottle at 99% still went through.

This checkpoint is a public showcase, so a couple of confident mistakes are better than parking that many frames. At {{ '%.2f'|format(threshold) }}, validation holds 14 frames. The misses at 76% and 85% stay held. The ones at 91%, 96%, and 99% are sorted. On the locked 300-image test, 4 frames stay unsorted and the other 296 are correct. The crushed can at 69% is one of the four. The test folder is larger now. On that set the same cutoff holds 6 frames and still sorts 6 confident mistakes.

Export

pip install onnx onnxruntime
python export_onnx.py --check --data-dir data_belt_stage1

That writes models/resnext50_metal_plastic.onnx and models/resnext50_metal_plastic.onnx.json. --check scores two metal and two plastic test photos with PyTorch and with ONNX Runtime. It stops if a logit moves by more than 0.0001.

Each frame

  1. Open the JPEG as RGB, including the phone EXIF rotation.
  2. Bilinear resize to {{ input_size }}×{{ input_size }}. Pillow matches training. OpenCV INTER_LINEAR lands on different pixels, so a belt app that uses it should re-score frames near {{ '%.2f'|format(threshold) }} before trusting the hold. OpenCV reads BGR. Swap to RGB before the resize.
  3. Divide by 255, subtract the mean, divide by the std.
  4. Send that tensor under the input name image.
  5. Read logits. Use the JSON class index.
  6. Softmax of the logits divided by the JSON temperature.
  7. The winning score under the JSON threshold is uncertain. Otherwise the label is the winning class.

Build the engine

/usr/src/tensorrt/bin/trtexec \
  --onnx=resnext50_metal_plastic.onnx \
  --saveEngine=/opt/replastics/resnext50_metal_plastic.engine \
  --fp16

The camera process opens that engine once and keeps it. FP16 is the runtime. This network at {{ input_size }} is small on an Orin. Rebuild the engine after a JetPack upgrade, and again after a new export.
